## 2. Differentiation thesis (5 bullets)

1. **Nobody couples capacity to allocation.** Every incumbent answers "how many are moving?" (UNHCR, IOM, IDMC) or "how many will move?" (Foresight). None answers **"how many can country X absorb, into which occupations and which subnational units, and what is the welfare-maximising assignment across a set of destinations?"** That is an optimisation problem and no open tool solves it.
2. **Nobody makes the model editable by the policymaker.** Atlas of Migration and Foresight are read-only outputs of someone else's assumptions. The differentiator is **assumption sliders with visible provenance**: change the housing-vacancy elasticity, watch the headroom recompute, export the assumption set as a signed JSON scenario others can reproduce.
3. **Nobody is self-hostable end-to-end.** Portals are SaaS; Foundry is $$$; kepler.gl is a viewer with no domain model. A **self-hosted, Docker-composable, air-gappable workspace** is what a ministry of interior or a national statistics office can actually deploy. This alone is the wedge.
4. **Nobody fuses the annual-official layer with the daily-preliminary layer in one coherent confidence model.** IDMC IDU (daily, preliminary), DTM (round-based), UNHCR (annual, validated), Frontex (monthly, detections-not-persons). A **single explicit tiered-confidence data model** — `validated | preliminary | modelled | estimated` — rendered as a visual property of every mark, does not exist anywhere.
5. **Nobody treats the connector layer as the product.** "Cross-agnostic" should mean a **connector SDK**: a source is a manifest declaring `{id, license, cadence, spatial_grain, temporal_grain, confidence_tier, fetch(), normalise() → CanonicalObservation}`. Sources become plugins. That is what makes the thing outlive any single API deprecation — and given UNHCR is replacing its portal in 2026 and DTM already broke clients with v3 keys, this is not theoretical.

## 3. MVP scoping: the 20% that carries 80%

**SHIP (v1):**

- **One globe, three layers.** deck.gl v9.4 `GlobeView` (Sept 2026: now supports pitch/bearing, trackpad gestures, elastic navigation bounds, full WebGPU layer parity). Layers: (a) choropleth of migrant stock / headroom on country polygons, (b) `ArcLayer` top-N bilateral corridors, (c) `ScatterplotLayer` of Missing Migrants incidents. Nothing else.
- **Frozen offline snapshot as the source of truth.** A `data/snapshot-2026-09.parquet` bundle built by an ETL step, committed or fetched once. The app **must run with the network off.** Live connectors are a refresh layer on top, never a dependency.
- **The Headroom Calculator** — one number per country with a fully exposed formula (§4), five sliders, and a "this is a screening estimate, not a forecast" banner.
- **The Allocation Solver** — a single min-cost assignment over ≤50 origins × ≤50 destinations, solved client-side in <2s. This is the thing that does not exist elsewhere.
- **Provenance drawer + model card page.** Copy Migration Data Portal and DRC Foresight respectively.
- **Scenario as URL.** Every state encodes to a shareable link and a downloadable JSON.

**CUT from v1 (looks essential, is not):**

| Cut | Why |
|---|---|
| Real-time streaming / websockets | No open source updates faster than daily (IDMC IDU is the fastest). "Live" here means a scheduled refresh with a visible `last_updated` stamp. Building websockets buys nothing and costs a week. |
| Subnational admin2 for all countries | Global admin2 geometry is ~500MB+. Do admin0 globally, admin1 for a 10-country pilot. |
| Agent-based / gravity-model migration simulation | Weeks of work, unvalidatable, and the output looks like fake science. Use a transparent LP instead. |
| User accounts, RBAC, multi-tenancy | Self-hosted single-workspace. Auth is a v2 problem. |
| ACLED integration | Licence forbids the AI use-case. Use GDELT + IDMC IDU instead. |
| Remittance / trade / climate layers | Interesting, not decision-relevant in v1. Ship the connector SDK so they can be added later without core changes. |
| 3D extruded population columns, terrain, satellite basemap | Costs framerate, adds no information. |
| LLM chat over the data | Guaranteed to hallucinate numbers. If included at all, it may only *navigate* (set filters, open panels) — never *state figures*. |

## 4. The two formulas the agent must implement exactly

**Absorptive headroom** for country *c*, horizon *h* years. Binding-constraint (Liebig minimum), not an average:

```
Headroom_c(h) = min_k { S_k }   for k in {labour, housing, education, health, fiscal}

S_labour   = Σ_o max(0, V_o,c − θ_o · U_o,c) / r_labour
             V_o,c = open vacancies in occupation o; U_o,c = unemployed residents matchable to o;
             θ_o ∈ [0,1] = domestic substitutability (slider, default 0.7);
             r_labour = labour-force participation rate of the migrant cohort (slider, default 0.75)

S_housing  = (VacantDwellings_c + h · NetCompletions_c) · AvgHouseholdSize_c · (1 − ReserveMargin)
S_education= (SchoolPlaces_c − Enrolled_c) / ChildShare_cohort
S_health   = (Physicians_c / TargetPhysiciansPer1k − Pop_c/1000) · 1000
S_fiscal   = AnnualIntegrationBudget_c / CostPerArrival_c
```

Every term is a slider with a cited default and a `confidence_tier`. **Occupation-level vacancy data (V_o,c) exists for roughly 40 OECD/EU countries, not 200.** The agent MUST implement a documented fallback (e.g. ILO employment-by-ISCO growth trend) and flag those countries as `modelled`, not hide the gap.

**Allocation** — min-cost flow, not a black box:

```
minimise  Σ_{o,d} x_od · ( w1·Dist_od + w2·(1 − Affinity_od) + w3·(1 − CapacityFit_d) − w4·Pref_od )
s.t.      Σ_d x_od = Demand_o  ∀o
          Σ_o x_od ≤ Headroom_d(h)  ∀d
          x_od ≥ 0 ;  x_od ≤ Quota_od (optional hard cap)
w1..w4 exposed as sliders, default (0.25, 0.25, 0.35, 0.15), Σw = 1
Affinity_od = normalised(language overlap, diaspora stock share, historical corridor volume)
Pref_od     = stated-preference weight; default 0 and labelled "no data" unless supplied
```

Solve with `javascript-lp-solver` or `glpk.js` in a Web Worker. Cap at 50×50 in v1.

## 5. The 8 ways the AI agent will fail, with the preventive instruction

| # | Failure | Instruction to embed verbatim in the build prompt |
|---|---|---|
| F1 | **Hallucinated endpoints.** Inventing `https://api.iom.int/v1/migration` and shipping it. | "You may only call a URL that appears in the `SOURCES.md` allowlist. Before writing any fetch, `curl -sI` the URL and paste the status line into a comment above the call. If a source is not reachable, mark it `status: UNVERIFIED` in `SOURCES.md` and implement it against the offline snapshot only. Never invent an endpoint path. Specifically: DTM API v3 requires a subscription key from `dtm-apim-portal.iom.int`; UNHCR RDF at `https://api.unhcr.org/population/v1/` needs none; World Bank Data360 paths must be read from `github.com/worldbank/open-api-specs` before use." |
| F2 | **Unbounded data downloads.** Fetching all of HDX at build time; 400MB TopoJSON. | "Hard budget: total initial page payload ≤ 8MB gzipped; any single asset ≤ 2MB. Country geometry = Natural Earth 1:110m simplified, TopoJSON, ≤ 700KB. Any fetch loop must have an explicit page cap and a byte budget that throws when exceeded. Pre-aggregate in the ETL step; the browser never downloads raw records." |
| F3 | **5fps globe.** 200k animated particles on `ArcLayer`, per-frame `setState`, re-created layers each render. | "Budget: ≥ 50fps on integrated GPU at 1440p. Render at most 200 arcs and 20,000 scatter points at once; anything more must be binned or aggregated server-side. Use deck.gl v9.4 with `updateTriggers`, never new layer instances per frame. Keep animation to `getWidth`/`getColor` transitions, no per-frame JS geometry. Add an FPS counter in dev mode and fail CI if the scripted flythrough drops below 45fps." |
| F4 | **Fake precision.** "Germany can absorb 1,247,893 migrants." | "Never render a capacity figure at more than 2 significant figures. Always render it as an interval with an explicit method label, e.g. `≈1.0–1.4M (screening estimate, binding constraint: housing)`. Every capacity output must name its binding constraint and link to the model card. Add the standing disclaimer: 'Screening estimate from public aggregates. Not a forecast. Not a basis for individual determinations.'" |
| F5 | **Scope sprawl.** 14 half-built panels, nothing works end-to-end. | "Build in this order and do not start step N+1 until step N runs end-to-end from a cold `npm install && npm run dev`: (1) globe + country choropleth from snapshot; (2) provenance drawer; (3) headroom calculator with sliders; (4) corridor arcs; (5) allocation solver; (6) scenario URL encode/decode; (7) live connector refresh; (8) incident layer. Anything not in this list goes into `BACKLOG.md`, not into the code." |
| F6 | **No offline snapshot — nothing runs.** Reviewer opens it, every API is down/keyed, blank globe. | "`npm run dev` with the network disabled must render a fully populated globe with all 200+ countries, working sliders and a working solver. Commit `data/snapshot/` (Parquet or gzipped JSON, ≤ 20MB total) produced by `scripts/etl/`. Live connectors are strictly an enhancement path behind a `REFRESH` button and a feature flag, never a load-time dependency." |
| F7 | **Unreadable dark intel UI.** Pure #000, 11px grey-on-grey, neon-on-dark choropleths that fail contrast. | "Dark surface base `#0B0E14`, not `#000`. Body text ≥ 13px at ≥ 7:1 contrast; all interactive labels ≥ 4.5:1. Tabular numerals for every figure. Sequential choropleths must be colourblind-safe and perceptually uniform (viridis/magma family) and must be validated against deuteranopia. Never encode a quantity by hue alone — always hue + one of size/opacity/pattern. Provide a light theme that is not an afterthought." |
| F8 | **Ethics ignored.** A UI that lets a user "optimise" people like freight; no individual-level data guardrail; enforcement framing. | "Hard rules: (a) no individual-level or re-identifiable record is ever ingested, stored or rendered — minimum aggregation unit is admin1 with n ≥ 100; (b) the allocation solver must display, adjacent to its output, a non-dismissible panel stating that outputs are advisory, that migrant preference and non-refoulement obligations are not modelled unless supplied, and that no automated determination about any individual may be derived; (c) ship `ETHICS.md` and a `MODEL_CARD.md` covering intended use, out-of-scope use, known bias by data source, and coverage gaps; (d) use neutral terminology — 'irregular arrival', never 'illegal'; label Frontex figures 'detections of border crossing, not persons'; (e) no predictive scoring of named individuals or ethnic groups, at any tier." |
