# Design record

How the MVP design was arrived at, kept so the reasoning is auditable rather
than asserted.

| File | What it is |
|---|---|
| `00-ground-truth-reference-brief.md` | The verified research compressed into one ground-truth brief: what data exists, at what latency, under what licence; which formulas are actually implementable; the rendering, UX and architecture constraints; the ethical hard rules. |
| `01-candidate-rigour-first.md` | Competing design A — optimised for a product an IOM/UNHCR/OECD analyst would not laugh at. |
| `02-candidate-impact-first.md` | Competing design B — optimised for a first-30-seconds reaction that is nonetheless truthful. |
| `03-candidate-platform-first.md` | Competing design C — optimised for modularity and longevity; the shipped MVP as a reference implementation of a platform. |
| `04-FINAL-mvp-design.md` | **Authoritative.** The synthesis, after a three-lens judge panel (buildability / impact-and-truth / platform-and-ethics) scored the candidates and named their fatal flaws. Where this disagrees with any candidate, this wins. |

The three candidates were written independently from the same research, each
committed hard to its lens rather than hedging toward the middle. The judges
scored harshly — the highest score any candidate received on any axis was 7/10.
The final design carries forward the best ideas from the losing candidates and
fixes every fatal flaw the judges found.
